## 实验

### 剔掉涉及词表外字的 CSC 训练样本

**背景**:字级词表 12,536 只含 6,328 个单汉字,覆盖 CJK 基本区的 30.1%。
词表外的字走 UTF-8 字节回退,一个字变三个 token;而 `char_to_id` 只取首个
token,于是 `撘`/`檡`/`暸` 在模型眼里**完全一样**(都是 `<0xE6>` = id 233)。

在 CSC 训练数据(sighan_wang271k,25 万对)上实测:

| | 占比 |
|---|---|
| 字次覆盖 | 99.92%(词表外仅 0.0835%) |
| 字种覆盖 | 85.9%(词表外 807 个不同字,占 14.1%) |
| **错字位置涉及词表外字** | **3.69%** |

最后一行是关键:词表外字在普通文本里只占万分之八,在**错字位置**上却占
3.69%,放大了 44 倍 —— 生僻字本来就更容易写错、更容易被误用。这 1.3 万处
的训练信号是错的:模型看到的输入分辨不出是哪个字,要求它输出的目标又不在
词表里。

**做什么**:训练时跳过 `len(tok.encode(c)) > 1` 的样本,看 F1 怎么变。

**预期**:少了 1.3 万个错误信号,可能微涨;但测试集里那部分错字仍然纠不了,
上限不变。所以是"去噪"而非"提升能力"的实验。

**代价**:一次训练 4.4 小时(315M)。改动量:`prepare/build_csc.py` 加一个
过滤开关。

**不做扩词表**:嵌入层变大、已发布的六个模型权重全部失配、新增的字在语料里
只出现几次到几百次学不出东西。代价远大于收益。

## 改进

### `id_to_char` 反查表对多 token 的字无解

`prepare/tokenizer.py` 的 `id_to_char()` 是"一个 id 一个字"的表,遇到
字节回退的字(三个 token)还原不回去 —— SIGHAN-15 的 707 条里有 15 条。

现在的做法是回避这个问题:`prepare/build_csc.py` 把原文一并写进测试集文件,
评测用原文当参照。这样评测口径不受编码影响,将来换 tokenizer 也不会漂移。

**正确做法**是用 tokenizer 的 `decode()` 重组字节序列。但只影响
`save/assets/csc_model.py` 里发布出去的推理代码(它没有原文可依,只能靠
反查表),优先级不高。

### 165M 的微调没跑到底

2026-07-26 的净室验证里跑通了起步:`make finetune-mt CKPT=models/BERTc-165M`
参数拼装正确,200 步内 loss 正常下降(cws 98.9→11.1,pos 3.37→0.74,
ner 180→10.1),但没跑完 5 个 epoch,没有最终指标。

已发布的 165M-MT / 165M-CSC 权重来自更早的训练,不是当前代码跑出来的。
315M 的 MT / CSC 用当前代码复现过(1.4705 / 0.8316,记录 1.4712 / 0.8346)。

**做什么**:`make -C prepare finetune SIZE=mid CKPT=models/BERTc-165M` 跑完,
对照记录的 1.4689 / 0.8308。

**代价**:MT 约 1.5 小时 + CSC 约 2 小时。
