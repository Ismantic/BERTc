## 会静默出错的地方

以下每条都满足同一个条件:改错了不抛异常、不打警告,训练跑完才发现。

### 整词掩码退化成逐字掩码

整词掩码要求「沁县」两个字一起遮。实现方式是给每个 token 一个 word id,
同一个词的字共享 id,掩码时按 word id 整组遮。

如果 `word_starts` 没生效,每个字拿到独立 id,整词掩码就退化成逐字掩码,
而训练照样跑、loss 照样降,不报错。

验证方法是切完块之后看词长分布:

```
1 字 54%   2 字 38%   3 字 5.7%   ≥4 字 2.6%      ← 正常
1 字 100%                                          ← 退化了
```

`docs/PRETRAIN.md` 的「验证产出」一节有现成代码。

### 预训练语料不能逐字编码

字模式下 tokenizer 只对**中文**一字一 token;英文单词整体成一个 piece,
空格成 `▁`。所以不能一个字一个字地编码 —— 那样英文会被拆碎。

`prepare/encode_corpus.py` 的做法是整串编码,再按字符游标把 piece 对回原文位置,
这样才能拿到词边界。MT / CSC 用的是纯中文短句,才可以逐字编。

同一个 tokenizer,两种编码方式,用错了不会报错,只是英文部分变成噪声。

### `det_labels` 必须按字比对,不能按 id

CSC 的检测头需要标注「这个位置错没错」。直觉写法是比对错句和正句的 token id。

问题:两个不同的字可能都落到 UNK 或同一个字节回退 token。按 id 比,
`撘` → `搭` 这样的错误会被判成「没错」,检测头就学到了错误的监督信号。

按字比对。实测 82 万对 CSC 数据里确实存在这种情况 —— 不是理论风险。

### `torch.from_file` 必须 `shared=True`

`shared=False` 要一份私有副本,80 GB 语料直接 `Cannot allocate memory`。
`shared=True` 走 MAP_SHARED,按页惰性加载。

这条会报错,但报错信息(内存不足)指向的方向不对,容易让人去调 batch size。

### 优化器的 no-decay 分组

weight decay 不应作用在 bias 和 LayerNorm 参数上。分组写错(例如按名字匹配
时遗漏),训练不会报错。

检查方法:打印 no-decay 组的参数量。正确的话**只有两万多**(几百个 bias 和
norm 向量),如果是几百万,说明把某些权重矩阵也划进去了。

## 架构选择

| 选择 | 替代方案 | 为什么 |
|---|---|---|
| **ScaledSinusoidal 位置编码** | RoPE | RoPE 要在每层 attention 里做旋转,带来 5–10% 速度损失。序列只有 512 时,RoPE 的外推优势用不上,收益抵不过损失。Sinusoidal 只在嵌入层算一次 |
| **GeGLU 前馈** | 标准 FFN | 同等参数下更好。代价是中间层要开 2/3 宽度补偿门控多出的那个矩阵 —— 所以是 2752 而不是 4096 |
| **LayerNorm 无 bias** | 带 bias | 少一组参数,效果无差别。ModernBERT 和 LLaMA 都这么做 |
| **全部 Linear 无 bias** | 带 bias | 同上。bias 在有 LayerNorm 的架构里基本是冗余的 |
| **pre-norm 且首层跳过** | post-norm | pre-norm 深层更稳。首层输入刚过 embedding 的 LayerNorm,再 norm 一次是浪费 |
| **简化 MLM 头** | Dense + LN + GeLU + bias | `logits = h @ embed.weightᵀ`,只有一个矩阵乘。原版 BERT 的 MLM 头是一整个变换块,微调时全部丢弃,预训练在这部分的算力不产生收益。这个简化在下游另有作用,见 CSC 那条 |
| **Megatron 初始化** | 标准 normal | 残差支路的输出投影按 ×1/√2L 缩放,深模型早期不容易炸 |
| **无 dropout** | dropout 0.1 | 预训练数据量远大于参数量,不存在过拟合,dropout 只拖慢收敛。代码里没有 dropout 配置项 —— 恒为 0 的旋钮只会让人以为它可调 |
| **绑定输入输出嵌入** | 独立 | 词表 12536 × 1024 ≈ 1300 万参数,占 165M 模型的 8%。绑定后省下来的参数放进层数更划算 |

### 为什么是字级词表

中文 BERT 通常用 2 万到 5 万的词表。BERTc 用 12536,**中文部分一字一 piece**。

好处是下游任务对齐特别干净 —— 分词、词性、实体、拼写纠错都是**字级**任务,
词表和任务粒度一致,不用处理「一个 token 跨了两个标注单元」。

代价见[做不到的事](#做不到的事)。

## 预训练配方

```
StableAdamW  β=(0.9, 0.95)  wd=0.01  eps=1e-6
Damped Cosine LR  8e-4 → 8e-5,warmup 510 步(6%)
固定 15% 整词掩码
梯度累积从 1 线性爬到峰值(前 5% 步)
grad clip 0.5
8500 步 × 有效 batch 4096 × 512 ≈ 17.4B token
```

| 选择 | 为什么 |
|---|---|
| **StableAdamW** 而非 AdamW | 按每个张量的梯度 RMS 裁剪有效学习率,bf16 下明显更稳。实现见 [`src/optim.py`](../src/optim.py),152 行,能看清裁剪到底裁的是什么 |
| **bias correction 折进 beta** | StableAdamW 的做法:不单独做修正,而是把它吸收进 β 的计算。少一处除法,数值上等价 |
| **固定 15% 掩码** | 动态 curriculum(15→30→15)在 v3 试过,消融显示固定 15% 就拿到了双 SOTA。代码还在(`src/masking.py`),默认关 |
| **梯度累积爬升** | 等价于 batch size warmup(Cramming 和 ModernBERT 都用)。前期小 batch 多做几次更新,后期大 batch 稳梯度。**需要与 LR warmup 对齐**:两个 warmup 独立计算,会在前几百步产生非预期的实际学习率组合 |
| **grad clip 0.5** | 比常见的 1.0 更紧。24 层在早期容易出梯度尖峰 |
| **warmup 6%** | Cramming 的推荐值 |
| **不用 EMA** | v3 用过,v4 关掉 —— 8500 步这个长度收益不明显,还多占一份显存 |
| **跨文档隔离** | 一个 512 的块里常常装了好几篇文章。不隔离,模型会学到跨文章的伪关联。用 `flex_attention` 实现,靠 `.seg` 文件记录每个 token 属于哪篇 |

### 中英语料按文档数配比,不是按 token 数

目标是中英 token 比 6:4。但英文文档平均比中文长得多,**按 18:10 的文档比
轮询,才换来 6:4 的 token 比**。

直接按 token 数配比也可以,但要先把所有语料编码完才知道总量 —— 那是 4.6 小时
之后的事。按文档数配比可以边编码边轮询,一遍过。

## 两个花整轮训练换来的否定结果

下面两条各花掉一次完整的预训练。

### 同源语料再 shuffle 一遍,收益接近零

早期版本试过「继续预训练」的路子:拿已经训好的模型,再喂一批数据接着训。
第二批数据是**同一份语料换个随机种子重新采样**的。

第一次用了语料的 12%,第二次采 8%,期望重叠 60%,还有 40% 是没见过的。
结果下游指标几乎完全持平(±0.0005)。

决定收益的不是有没有没见过的句子,而是分布有没有变。同一份语料重采样分布
不变,要继续预训练就得换真正不同的语料源。

### 退火用 QA 数据,被模板污染了

另一次试的是「退火」:训练末期换一批更高质量的数据,用小学习率再训一段。
选的是某个语料的 QA 子集,想着问答格式对下游任务更友好。

那批数据里 30–50% 是「问题:/答案:」的模板文本,模型学到的是模板。加上英文
占了 64%(英文文档平均比中文长 3.5 倍),而下游任务全是中文。下游提升在
±0.002 以内。

这两条是当前配方从零训练、一次训到底、不做 CPT 也不做退火的原因。

## 微调的三个结论

### POS loss 必须加权

MT 是 CWS + POS + NER 的联合训练,loss 是三项加权和。

用默认权重(α=0.5)时 POS loss 只占总梯度的 1.6% —— POS 是 27 分类、每个
位置都有标签,单位置 loss 天然比 CRF 的序列 loss 小一个量级,结果是基本没学。

改成 α=2,POS 准确率涨 0.02。这是 BERTc 综合超过 MacBERT-Large 的唯一来源,
CWS 还落后 0.0016,NER 持平。

联合训练里 loss 权重不是调参,是让每个任务都能被学到的前提。配之前先打印
各项 loss 的实际量级。

### CSC 的纠错头必须与词嵌入绑权重

预训练的 MLM 头就是 `h @ embed.weightᵀ`,训完之后隐状态 `h` 已经和嵌入空间
对齐。CSC 的纠错头做的是同一件事(在词表上预测该是哪个字),换成随机初始化
的 Linear 等于把这层对齐丢掉重学,而微调数据只有 25 万对,学不回来。

F1 差 0.05。这也是[简化 MLM 头](#架构选择)的回报 —— 头越简单,下游能直接
继承的部分越多。

### CSC 调参:8 次实验测出来的

同一个 v4-Large 骨干,只改一处配置,各跑一遍:

| 改动 | F1 |
|---|---|
| v4-Mid 同 setup 重跑(噪声基准) | 0.8265 |
| b32 lr5e-5 10ep(基线) | 0.8281 |
| + det_weight 0.5 | 0.8291 |
| + warmup 0.05 | 0.8299 |
| b16 lr5e-5 10ep | 0.8303 |
| 基线 setup,换 seed | 0.8341 |
| + warmup 0.2 | 0.8343 |
| **lr 3e-5**(最终采用) | **0.8346** |

结论:lr 3e-5 优于 5e-5(+0.0065),warmup 0.2 也有效(+0.0062),
batch 16 和 det_weight 0.5 没有明显帮助。

**但最重要的一行是「换 seed」**:同一套配置只换随机种子,F1 从 0.8281 跳到
0.8341,差 0.006。而表里排名前几的改动,增益也就是这个量级。

SIGHAN-15 只有 707 条,单条句子的对错就值 0.0014。**这个测试集上 ±0.005 到
±0.01 的波动是噪声,不是效果。** 拿单次运行的 0.002 差距下结论没有意义 ——
上表里除了 lr 和 warmup 那两条(增益 0.006,勉强出噪声),其余都不能算数。

(表中数字是修正 [评测口径](#评测口径) 之前测的,当时的 0.8346 现在是 0.8388。
它们之间的相对关系不受影响。)

### 315M 用 5 epoch 严重欠训

165M 用 5 epoch 就到位了,315M 不行,要 10 epoch。

不是通用规律,是这个数据量(25 万对)和参数量的组合决定的。别把小模型的
epoch 数直接搬给大模型。

## 评测口径

评测口径要在训练之前定死,不能因为数字难看就改。

- **MT 的指标在 dev 前 2000 句上测**,不是全量 21,143 句。因为训练时就是用
  前 2000 句选 `best.pt` 的 —— 报告指标必须和选模型的口径一致,否则等于用
  测试集选模型。全量上的数字也一并公布(1.4646)。
- **CSC 用 SIGHAN-15 官方 707 条 + PyCorrector 口径**。这是这个任务的通行标准,
  换口径就没法跟别人比。
- **CSC 评测的参照必须是原文,不能是 id 还原的文本**。id → 字是有损的
  (707 条里有 16 条还原不回去),用还原文本当参照会让 F1 虚高 **+0.0059**。
  做法是把原文一并存进测试集文件。

参照用原文还有个好处:评测口径免疫编码问题,将来换 tokenizer 也不会漂。

### correct() 不使用检测头

`BERTcForCSC.correct()` 只用纠错头的 argmax,**不用检测头**。检测头是训练时的
辅助信号,推理不参与。

用 det 过滤会改变报告指标的口径。例如 `我今天很稿兴`,det 给 0.98,但 cor
的 top-1 仍是 `稿`(0.224),`高` 排第 4(0.115),所以不会改。降阈值也没用,
top-1 是原字时阈值不起作用。

`save/csc.py` 会把这种情况标成「存疑」显示出来,能直观看到模型「知道有错但
选不出字」的状态。

## 做不到的事

### 字级词表覆盖不了所有汉字

词表 12,536 里只有 **6,328 个单汉字,覆盖 CJK 基本区的 30.1%**。词表外的字
走 UTF-8 字节回退,一个字变三个 token;而 `char_to_id` 只取首个 token,
于是 `撘` / `檡` / `暸` 在模型眼里**完全一样**(都是 `<0xE6>`)。

在 CSC 训练数据(249,975 对)上实测:字次覆盖 99.92%,字种覆盖 85.9%
(词表外 807 个不同字)。词表外字在普通文本里只占万分之八,在错字位置上
占 3.69%,放大 44 倍 —— 生僻字本身更容易写错。

但**这 3.69% 里绝大多数仍然可学**。按错字和正字分别是否在词表内拆开:

| | 位置数 | 占错字位置 | 例 |
|---|---|---|---|
| 都在词表内 | 336,395 | 96.31% | |
| 只有**错字** OOV | 12,330 | 3.53% | 錓→康、茌→在 |
| 只有**正字** OOV | 524 | 0.15% | 枚→敉、踏→遢 |
| 两者都 OOV | 42 | 0.01% | 蒉→篑 |

「錓→康」这类输入模糊但目标在词表内,模型可以从上下文学出来,属于困难样本
而非错误标注。真正无法学习的是正字 OOV 的那 566 个位置,**占错字位置
0.16%**。

SIGHAN-15 测试集上同样如此:556 个错字位置里,因正字不在词表而注定纠不对的
只有 1 处(`增→噌`),**F1 的理论上限损失 0.0014**。

所以词表覆盖不是当前 CSC 指标的瓶颈。扩词表的代价(嵌入变大、已发布的六个
模型权重全部失配、新增字在语料里只出现几次学不出来)远大于这 0.0014。

### 预训练无法逐位复现

Wapic 的分词在 2026-07 变过,词边界与训练已发布模型时不同 —— PD-1998 dev 上
26.1% 的句子至少有一处差异。词表、架构、配方都没变,能复现的是同等水平的
模型,不是同一个模型。

微调可以复现:评测路径一位不差,重新训练 MT 差 −0.0007、CSC 差 −0.0030,
都小于训练自身的波动。
